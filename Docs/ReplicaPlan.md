# План ручного создания новой Elite

[Контрольные точки оригинала](ReplicaCheckpoints.md) · [Правила сравнения](ReplicaComparison.md)

План подготовлен по исходникам конкретного ELITE3HL.TRD и сохранённым отчётам разбора.
Он предназначен для отдельного рабочего чата и последовательной ручной реализации
нового проекта в стиле L&M. Папка новой игры ещё не выбрана и не создана этим этапом.

## Согласованная цель

Улучшить рендер, плавность, отзывчивость и темп полёта. Сохранить миссии, экономику,
оборудование и остальные правила оригинала вместе с их фактическими особенностями.
Сохранить утверждённые интервалы восстановления щитов, охлаждения, перезарядки и других
механизмов независимо от частоты CPU и стоимости рисования. Интерфейс менять точечно.

Математика и рендер исследуются до уровня форматов чисел, промежуточных результатов,
округления, переполнения, видимости, отсечения и отдельных пикселей. Оптимизация должна
иметь измеримый выигрыш и явно проверенную область воздействия.

## Как пользоваться списком

- Один рабочий заход — один пункт `Pxx.yy`, выбранный пользователем. Глава содержит несколько таких заходов.
- Перед изменением согласуются его цель, результат и файлы. После проверки работа останавливается.
- Все пункты изначально открыты. Наличие исходника или старого отчёта не означает выполнения переноса.
- Галочка ставится после фактического результата и его принятия пользователем.
- Сначала читаются контрольные точки соответствующей главы. У каждой есть исходные символы, состояния и сценарии.
- Неразрешённый вопрос фиксируется отдельно. Он не заменяется вымышленным адресом, периодом или правилом.
- Адреса памяти и размещение определяет пользователь. Git index принадлежит пользователю.
- Новые сборки и исполняемые проверки требуют отдельного разрешения для нового этапа либо выполняются пользователем.
- При неизвестной связи анализ уточняет текущий пункт, а не запускает соседнюю реализацию автоматически.

Для повторяемого цикла оптимизации используется дополнительный ID, например `P18.03-R02`.
Принятые прошлые записи не переписываются, чтобы сохранялись решение и результат сравнения.

## Устройство будущего проекта

Образец организации — текущий L&M: Builder, Source, Includes, Tools, Tmp и результат TRD
в корне. Конкретные модули, файлы подключения, количество проходов и карта памяти
принимаются в P04, они не копируются автоматически.

Образцы оформления структур и переменных:
[HoMM/Includes/Structs/Game_Config.inc](../../HoMM/Includes/Structs/Game_Config.inc) и
[HoMM/Includes/Variables/Game_Config.inc](../../HoMM/Includes/Variables/Game_Config.inc).
Здесь видны F-типы, вложенные поля, битовые схемы и именованные обращения.
Стиль будущих комментариев и инструкций следует актуальным правилам пользователя.

Оригинал остаётся в этом проекте. Материалы исследования и проверки хранятся в Tools,
в Tmp помещаются воспроизводимые временные результаты. Эталонные снимки и ресурсы
не должны становиться единственными экземплярами данных внутри Tmp.

## Журнал одного принятого пункта

| Поле | Заполняется при выполнении |
|---|---|
| ID | выбранный пункт Pxx.yy |
| Цель | одна конкретная работа |
| Контрольные точки | точные ID из каталога |
| Исходные условия | снимок, параметры, профиль времени |
| Файлы | реально изменённые файлы новой игры или документации |
| Проверка | статическая, исполнение оригинала, исполнение новой версии, измерение времени |
| Результат | значения, первое расхождение либо подтверждённое совпадение |
| Ограничения | что данным сценарием не проверялось |
| Решение | принятие пользователем либо перечень требуемых исправлений |
